# Pipeline CPU Test Data Suite (測資說明)

以下為您設計的 5 組測試資料（測資），可用於 ModelSim/Questa 模擬，或直接在 DE2-115 開發板上透過撥碼開關（`SW[15:0]`）與手動時脈（`KEY[0]`）進行驗證。

---

## 1. 測資格式說明
板子上的撥碼開關 `SW[15:0]` 對應的輸入欄位如下：
*   `SW[15:14]` = **Rt 暫存器選擇** (2-bit: `00`=R0, `01`=R1, `10`=R2, `11`=R3)
*   `SW[13:12]` = **Rs 暫存器選擇** (2-bit)
*   `SW[11:8]`  = **Opcode** (4-bit)
*   `SW[7:0]`   = **Data / 立即值** (8-bit)

手動執行時，在 `SW` 設定好一組指令後，**按一下 `KEY[0]` 再放開**即代表送入一個 Clock 週期。

---

## 2. 5 組測試情境設計

### 測資 1：基本暫存器載入與算術運算（無 Hazard）
*   **目的**：驗證 `LOAD` 與 `ADD` 的基本功能與 4-stage 管線的基本延遲（無衝突發生）。
*   **時序指令序列**：
    1.  `Cycle 1`: `LOAD R1, 0x05` (R1 載入 5) ── **`SW = 0x1005`** (`00 01 0000 00000101`)
    2.  `Cycle 2`: `LOAD R2, 0x07` (R2 載入 7) ── **`SW = 0x2007`** (`00 10 0000 00000111`)
    3.  `Cycle 3`: `NOP` (空指令) ── **`SW = 0x0F00`** (`00 00 1111 00000000`)
    4.  `Cycle 4`: `NOP` (空指令) ── **`SW = 0x0F00`**
    5.  `Cycle 5`: `ADD R1, R2` (計算 R1 <= R1 + R2 = 12) ── **`SW = 0x9200`** (`10 01 0010 00000000`)
    6.  `Cycle 6~8`: 持續輸入 `NOP` (送入 **`SW = 0x0F00`**) 以讓管線執行完畢。
*   **預期結果**：
    *   `Cycle 4` 結束後，七段顯示器選擇 Rs=R1 應顯示 `05`。
    *   `Cycle 5` 結束後，選擇 Rs=R2 應顯示 `07`。
    *   `Cycle 8` 結束後，選擇 Rs=R1 應顯示 `0C` (十六進制的 12)。
    *   整個過程中，綠色 LED 燈 `LEDG[0]` (Hazard 偵測) 保持熄滅 (`0`)。

---

### 測資 2：EXE 階段資料衝突與前饋 (EXE Forwarding)
*   **目的**：驗證當下一道指令需要使用「前一次運算（尚在 EXE 階段）的結果」時，管線能否正確偵測衝突並前饋資料。
*   **時序指令序列**：
    1.  `Cycle 1`: `LOAD R1, 0x0A` (R1 載入 10) ── **`SW = 0x100A`**
    2.  `Cycle 2`: `LOAD R2, 0x03` (R2 載入 3) ── **`SW = 0x2003`**
    3.  `Cycle 3`: `SUB(A-B) R1, R2` (R1 <= R1 - R2 = 7) ── **`SW = 0x9500`**
    4.  `Cycle 4`: `AND R1, R2` (R1 <= R1 AND R2 = 7 AND 3 = 3) ── **`SW = 0x9300`**
        *(註：此指令讀取 R1，而上一個指令的 R1 運算結果尚在 EXE 暫存器中)*
    5.  `Cycle 5~7`: 持續輸入 `NOP` (送入 **`SW = 0x0F00`**)。
*   **預期結果**：
    *   在 `Cycle 4` 時，`AND` 指令處於 Decode 階段，前饋單元應偵測到 R1 的 EXE 衝突。
    *   綠色 LED 燈 **`LEDG[0]` (Hazard 偵測) 正確亮起 (`1`)**，表示 Forwarding 運作中。
    *   管線無 Stall (正常推進)，`Cycle 7` 結束後 Rs=R1 應顯示 `03`。

---

### 測資 3：同時 EXE 與 WB 階段資料衝突與前饋 (Simultaneous EXE & WB Forwarding)
*   **目的**：驗證管線能否同時正確處理「前一次運算（在 EXE 階段）的結果」與「前前次運算（在 WB 寫回階段）的結果」所產生的資料衝突。
*   **時序指令序列**：
    1.  `Cycle 1`: `LOAD R1, 0x10` (R1 載入 16) ── **`SW = 0x1010`**
    2.  `Cycle 2`: `LOAD R2, 0x04` (R2 載入 4) ── **`SW = 0x2004`**
    3.  `Cycle 3`: `SUB(B-A) R1, R2` (計算 R1 <= R2 - R1 = 4 - 16 = -12 = 244) ── **`SW = 0x9900`**
        *(註：此指令同時讀取 R2 與 R1。R2 為前一次寫入，在 EXE 階段，產生 EXE 衝突；R1 為前前次寫入，在 WB 階段，產生 WB 衝突)*
    4.  `Cycle 4~6`: 持續輸入 `NOP` (送入 **`SW = 0x0F00`**)。
*   **預期結果**：
    *   在 `Cycle 4` 時，`SUB` 處於 Decode 階段，前饋單元同時前饋 EXE（對應 R2）與 WB（對應 R1）階段的暫存器值。
    *   綠色 LED 燈 **`LEDG[0]` (Hazard) 亮起**。
    *   `Cycle 6` 結束（即 `Cycle 7` 開始）後，Rs=R1 應顯示 `F4` (十六進制的 244)。

---

### 測資 4：多時序除法管線暫停 (DIV Stall)
*   **目的**：驗證執行除法時，管線能否正確暫停 (Stall) 8 個時脈週期，並在結束後恢復正常。
*   **時序指令序列**：
    1.  `Cycle 1`: `LOAD R1, 0x30` (R1 載入 48) ── **`SW = 0x1030`**
    2.  `Cycle 2`: `LOAD R2, 0x06` (R2 載入 6) ── **`SW = 0x2006`**
    3.  `Cycle 3`: `NOP` ── **`SW = 0x0F00`**
    4.  `Cycle 4`: `NOP` ── **`SW = 0x0F00`**
    5.  `Cycle 5`: `DIV R1, R2` (計算 R1 <= R1 / R2 = 8) ── **`SW = 0x9800`**
    6.  `Cycle 6`: `ADD R1, R2` (下一道運算，將被 Stall 暫停) ── **`SW = 0x9200`**
    7.  `Cycle 7~16`: 撥碼開關設為 `NOP`，重複按 `KEY[0]` 送入時脈。
*   **預期結果**：
    *   在 `DIV` 進入 EXE 階段時，**`LEDG[1]` (Exe Busy) 亮起**，管線暫停 8 個週期。
    *   在暫停的 8 個週期內，左側顯示 opcode 的七段顯示器 `HEX4` (IF/ID) 與 `HEX6` (ID/EXE) 會維持鎖定在除法 opcode `8`。
    *   Stall 結束後，`LEDG[1]` 自動熄滅，管線恢復前進。
    *   最終 Rs=R1 應顯示 `08`。

---

### 測資 5：除以零防錯與 Bypass
*   **目的**：驗證當除數為 0 時，除法器能否自動跳過 8 週期的 Stall，直接輸出錯誤值 `0xFF`。
*   **時序指令序列**：
    1.  `Cycle 1`: `LOAD R1, 0x15` (R1 載入 21) ── **`SW = 0x1015`**
    2.  `Cycle 2`: `LOAD R2, 0x00` (R2 載入 0) ── **`SW = 0x2000`**
    3.  `Cycle 3`: `NOP` ── **`SW = 0x0F00`**
    4.  `Cycle 4`: `NOP` ── **`SW = 0x0F00`**
    5.  `Cycle 5`: `DIV R1, R2` (計算 21 / 0) ── **`SW = 0x9800`**
    6.  `Cycle 6`: `ADD R1, R2` ── **`SW = 0x9200`**
    7.  `Cycle 7~10`: 持續輸入 `NOP` (送入 **`SW = 0x0F00`**)。
*   **預期結果**：
    *   當 `DIV` 進入 EXE 階段時，由於除數為 0，管線**不會發生 Stall**，綠色 LED 燈 `LEDG[1]` (Exe Busy) 保持熄滅 (`0`)。
    *   管線以正常速度推進（無 8 週期的停頓），且 R1 被寫入錯誤旗標值 `FF`。
